보안 원칙

확인할 수 없는 요청은
통과시키지 않습니다

Symbolon Gateway와 Symbolon ID는 장애가 생기더라도 허가받지 않은 접근이 일어나지 않도록 설계했습니다. 이 페이지에서는 두 제품이 지키는 보안 원칙을 소개합니다.

보안 리뷰

독립 보안 리뷰, 세 차례의 수정과 수정 재검증을 거쳤으며, 출시 시점 기준 알려진 높은 심각도 이상의 문제는 없습니다. 상세는 요청 시 제공합니다.

취약점이 전혀 없다거나 보안 인증, 규정 준수 인증을 받았다는 뜻은 아닙니다. 도입을 검토하는 고객에게는 리뷰 결과를 따로 안내해 드립니다.

장애 때문에 로그인이나 권한을 확인할 수 없으면 요청을 통과시키지 않고 안내 페이지를 보여 줍니다. 장애 중에 로그인 없이 접속을 허용하는 설정은 처음부터 두지 않았습니다.

{{include name="i-eye"}}

확인된 사용자 정보만 전달

서비스에는 게이트웨이가 직접 확인한 사용자 정보만 전달됩니다. 외부에서 사용자 정보를 위조해 보내도 서비스에는 전달되지 않습니다.

{{include name="i-globe"}}

서비스마다 분리된 로그인 상태

로그인 상태는 서비스마다 따로 관리합니다. 한 서비스의 로그인 정보를 다른 서비스에서 쓸 수 없습니다.

{{include name="i-server"}}

허용된 서버로만 연결

게이트웨이는 관리자가 미리 허용한 내부 서버로만 요청을 보냅니다. 조직마다 연결할 수 있는 서버를 따로 정합니다.

관리와 운영

비밀번호만으로는
관리자 권한을 쓸 수 없습니다

두 제품 모두 관리자 계정은 2단계 인증을 거쳐야 쓸 수 있습니다. 중요한 변경은 한 사람이 혼자 반영할 수 없게 했습니다.

두 사람의 확인

운영 환경의 변경은 작성자가 아닌 다른 관리자가 승인합니다. 접근 범위를 넓히는 변경은 보안 담당자가 승인해야 합니다.

서명된 설정

게이트웨이는 관리 서버가 서명한 설정만 적용합니다. 중간에 바뀐 설정은 적용하지 않습니다.

감사 기록

관리 작업은 모두 기록으로 남고, 기록이 나중에 고쳐지거나 지워지지 않았는지 검증할 수 있습니다.

비밀 정보 보호

연동에 쓰는 비밀 정보는 암호화해서 저장합니다. 두 제품은 계정과 데이터를 따로 두어 한쪽 문제가 다른 쪽으로 번지지 않게 했습니다.

개발과 릴리스

알려진 취약점이 있으면
릴리스하지 않습니다

외부 라이브러리는 꼭 필요한 것만 씁니다. 릴리스 전에 의존성 취약점 검사를 하고, 알려진 취약점이 하나라도 있으면 릴리스하지 않습니다.

실제 환경에 가까운 자동 시험

실제 프로그램과 데이터베이스를 실행해 정상 동작은 물론 장애나 공격 상황에서 어떻게 동작하는지도 자동으로 시험합니다.

실제 브라우저 시험

관리 콘솔은 실제 브라우저로 화면을 하나씩 열어 오류와 접근성 문제를 확인합니다.
