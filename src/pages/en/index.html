What changes

One place to manage sign-in
for all your internal tools

Internal tools and dashboards are often reached directly by server address. Some have no sign-in at all, others each have their own accounts, so it is hard to see who can reach what.

http://server-address:port No encryptionAnyone with the address gets inSeparate sign-in per tool

With Symbolon Gateway

https://dashboard.corp.example HTTPSAllowed groups onlyOne sign-in with a company account

Internal domains and HTTPS

Each service gets an internal domain and opens over HTTPS. Certificates are issued automatically and renewed before they expire.

Group-based access

Choose which groups may use each service. Only members of those groups can get in.

No changes to your services

The gateway handles sign-in and access checks, so you don't have to build sign-in into each service.

How it works

From sign-in
to service

Users open the internal address as usual. There is nothing to install.

  1. 1

    Sign in once with a company account

    The first visit shows the sign-in page. After that, other internal services open without signing in again.

  2. 2

    The gateway checks access

    On every request, the gateway checks who the user is and whether they may use this service.

  3. 3

    Only verified users reach the service

    Only requests from users with access are passed on. Everyone else sees a notice page.

Two products

Use them separately
or together

Symbolon Gateway

Gateway for internal services

Opens internal web services on HTTPS addresses and checks sign-in and access on every request before passing it on.

  • Service registration, internal domains, automatic certificates
  • Sign-in, allowed groups and two-step verification per service and path
  • Approved changes with rollback, live monitoring, audit log
On its own connects to the standard OIDC sign-in server you already useLearn more

Symbolon ID

Sign-in (SSO) server

Manages your company's users and groups in one place and lets people use many services with a single sign-in.

  • Users and groups, passwords and two-step verification with an authenticator app
  • Sign-in and account pages for end users
  • Standard OIDC, so other internal products can connect directly
On its own becomes the shared sign-in server for your internal productsLearn more

Security principles

Requests that can't be verified
don't get through

  • If an outage prevents checking sign-in or access, the request is blocked and a notice page is shown.
  • The gateway applies only configuration signed by the management server.
  • Administrator accounts in both products require two-step verification.
  • Every administrative action is recorded in the audit log.
Read the security principles

An independent security review, three rounds of fixes and re-verification are complete; as of release there are no known issues of high severity or above. Details on request.

This does not mean there are no vulnerabilities or that the products hold a security certification.
