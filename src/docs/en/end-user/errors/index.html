Access denied and temporary outage screens

What the access denied (403) and can't-reach-sign-in-service (503) screens that appear instead of a service mean, and what to do

On this page
  • Request ID
  • You don't have access (403)
  • Can't connect to the sign-in service (503)
  • Temporarily unavailable (503)
  • For administrators

This page explains the short message screens that sometimes appear instead of a service, and what to do when you see one. These screens come from the gateway that checks access in front of the service.

Request ID#

At the bottom of every message screen there's a 요청 ID (Request ID), a long value of letters and numbers separated by hyphens. Administrators use it to look up what happened at that moment. When you ask for help, send a screenshot or the request ID, and include the time and the address you were opening.

You don't have access (403)#

What it means: You're signed in, but you aren't on the list of people who can use this service (or this menu). For security, the screen doesn't say which group you'd need.

What to do:

  1. Check whether this service needs a different account. If so, sign out and sign in again with the right account.
  2. If you need access, contact the service administrator and include the request ID. (The contact text on the screen may differ by organization.)
  3. If you still see this screen after you've been given access, sign out and sign in again. Access changes take effect when your sign-in is checked again (usually within 1 hour).

There are a few similar screens.

Can't connect to the sign-in service (503)#

What it means: The server that handles sign-in (Symbolon ID) isn't responding for the moment. So that no one gets in without being checked, the gateway doesn't let you through and shows this message instead. It isn't a problem with your account or your access.

What to do:

  1. Wait 30 seconds to 1 minute, then refresh.
  2. If it's still the same after a few minutes, tell the service administrator or help desk and include the request ID.

Temporarily unavailable (503)#

This screen comes with a message such as "게이트웨이가 아직 접근 정책을 받지 못했습니다" (The gateway hasn't received its access policy yet) or "최신 접근 정책을 확인하지 못하고 있습니다" (The latest access policy can't be confirmed). It means the gateway is restarting, or there's a problem with its connection to the management server. Try again in a little while. If it keeps happening, tell the service administrator and include the request ID.

For administrators#

  • Administrators can use the request ID on the message screen to find the record of that request in the access events of the Symbolon Gateway console (Access events). For allowed requests, the same request ID is also passed to the service, so you can match it against the service's logs. Denied requests never reach the service, so they aren't in its logs (Headers the Backend receives).
  • Administrators can change the contact text shown on the 403 screen.
  • When a request that isn't signed in is not a browser page navigation but a request that loads data within a page, it isn't sent to the sign-in screen. Instead it gets a response saying sign-in is required (401) and the address to start signing in (Bearer token APIs).
