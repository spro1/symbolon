Product overview

What Symbolon Gateway and Symbolon ID do, how they work, key features, deployment options and recommended sizing

What the products do#

Symbolon Gateway is a gateway you put in front of internal web services. When someone opens a service, the gateway first checks that they are signed in and allowed to use that service, and forwards only verified requests. Your services don't need to build their own sign-in or permission checks.

Symbolon ID is a sign-in server that manages users, groups, passwords and two-factor authentication. It speaks standard OIDC, so besides Symbolon Gateway you can connect any application that supports OIDC.

The two products are designed to work together, but you can also use either one on its own. Used together, sign-in settings are configured automatically when you register a service, and signing out in one place signs the user out of the other services within seconds.

How it works#

  1. A user opens an internal service and sees the Symbolon ID sign-in page. After signing in once, they don't have to sign in again for other services connected the same way.
  2. Symbolon Gateway checks who the user is and whether they belong to a group allowed for that service.
  3. Only requests that pass the check reach the service, together with the verified user information.

Deployment options#

The products are designed to run on virtual machines, in containers, or on Kubernetes. In 1.0 beta, the only setup verified end to end is the evaluation setup on a single machine. Files for building container images and for running the products as system services are included, but they have not yet been verified on real servers. The Kubernetes setup is provided as a reference example.

Recommended sizing#

Size the gateway by the number of concurrent users and the number of protected domains. The recommendations below leave enough headroom for the service to keep running if one machine fails.

Security principles#

  • Requests from users who can't be verified are not forwarded to the service.
  • Configuration sent to gateways is signed, and a gateway applies only configuration whose signature checks out.
  • Both products require two-factor authentication for admin sign-in.
  • Admin actions are recorded in an audit log that can be checked for tampering.

An independent security review, three rounds of fixes and re-verification are complete; as of release there are no known issues of high severity or above. Details on request. Send requests through the GitHub repository issues (https://github.com/spro1/symbolon/issues).

Beta status and maker#

1.0.0-beta.1 is a beta release for evaluation and validation. Before using it in production, we recommend a PoC in your environment to confirm behavior and sizing.
