제품 소개

Symbolon Gateway와 Symbolon ID가 하는 일, 동작 방식, 주요 기능, 설치 형태, 권장 사양

두 제품이 하는 일#

Symbolon Gateway는 사내 웹 서비스 앞에 두는 게이트웨이입니다. 사용자가 서비스에 접속하면 로그인했는지, 그 서비스를 쓸 권한이 있는지 먼저 확인하고, 확인을 통과한 요청만 서비스로 전달합니다. 그래서 서비스마다 로그인과 권한 확인 기능을 따로 만들 필요가 없습니다.

Symbolon ID는 사용자 계정과 그룹, 비밀번호와 2단계 인증을 관리하는 로그인 서버입니다. 표준 OIDC를 지원하므로 Symbolon Gateway뿐 아니라 OIDC를 지원하는 다른 애플리케이션도 연결할 수 있습니다.

두 제품은 함께 쓰도록 설계했지만 하나만 따로 쓸 수도 있습니다. 함께 쓰면 서비스를 등록할 때 로그인 설정이 자동으로 맞춰지고, 사용자가 한 곳에서 로그아웃하면 다른 서비스에서도 수 초 안에 로그아웃됩니다.

동작 방식#

  1. 사용자가 사내 서비스에 접속하면 Symbolon ID 로그인 화면이 나타납니다. 한 번 로그인하면 같은 방식으로 연결된 다른 서비스에서는 다시 로그인하지 않아도 됩니다.
  2. Symbolon Gateway가 사용자가 누구인지, 그 서비스에 허용된 그룹에 속해 있는지 확인합니다.
  3. 확인을 통과한 요청만 서비스로 전달됩니다. 이때 서비스는 확인이 끝난 사용자 정보를 함께 받습니다.

주요 기능#

영역기능
서비스 보호서비스와 경로마다 로그인이 필요한지, 어떤 그룹을 허용할지 정합니다. 중요한 경로에서는 2단계 인증을 한 번 더 요구할 수 있습니다.
인증서서비스 도메인의 TLS 인증서를 자동으로 발급하고, 만료되기 전에 알아서 갱신합니다.
변경 관리설정을 바꾸면 검증을 거쳐 배포되고, 문제가 생기면 이전 상태로 되돌릴 수 있습니다. 운영 환경의 변경은 다른 담당자가 승인해야 배포됩니다.
계정과 로그인사용자와 그룹 관리, 비밀번호 정책, 인증 앱을 이용한 2단계 인증, 통합 로그인(SSO)을 제공합니다.
즉시 로그아웃계정을 비활성화하거나 세션을 종료하면 수 초 안에 모든 서비스에서 로그아웃됩니다.
관리 콘솔서비스 등록, 접근 정책, 변경 승인, 실시간 트래픽 현황, 접근 기록을 웹 화면에서 관리합니다. 관리자가 로그인할 때는 2단계 인증이 필수입니다.
기록관리 작업은 감사 로그에 남고, 거부된 접근은 접근 이벤트에서 확인할 수 있습니다.

설치 형태#

가상 머신(VM)에 설치하는 형태, 컨테이너로 실행하는 형태, Kubernetes에 배치하는 형태를 모두 염두에 두고 설계했습니다. 다만 1.0 베타에서 처음부터 끝까지 검증한 구성은 장비 한 대에 설치하는 평가판뿐입니다. 컨테이너 이미지를 만드는 파일과 서버에서 서비스로 실행하기 위한 설정 파일은 함께 제공하지만, 실제 서버에서의 검증은 아직 진행하지 않았습니다. Kubernetes 구성은 참고용 예시로 제공합니다.

권장 사양#

게이트웨이 장비의 대수와 사양은 동시 사용자 수와 보호할 도메인 수에 따라 정합니다. 아래 사양은 장비 한 대가 멈춰도 서비스가 계속 동작하도록 여유를 두고 잡은 값입니다.

1.0 베타 기준 산정치 — macOS 단일 장비 실측을 바탕으로 실측의 50%로 보수적으로 잡은 값. Linux 서버 실측과 고객 PoC에서 확정합니다.

보안 원칙#

  • 사용자를 확인할 수 없는 요청은 서비스로 전달하지 않습니다.
  • 게이트웨이에 배포되는 설정에는 서명이 붙어 있으며, 게이트웨이는 서명을 확인한 설정만 적용합니다.
  • 두 제품 모두 관리자가 로그인할 때 2단계 인증이 필수입니다.
  • 관리 작업은 변조 여부를 확인할 수 있는 감사 로그에 기록됩니다.

독립 보안 리뷰, 세 차례의 수정과 수정 재검증을 거쳤으며, 출시 시점 기준 알려진 높은 심각도 이상의 문제는 없습니다. 상세는 요청 시 제공합니다. 요청은 GitHub 저장소(https://github.com/spro1/symbolon/issues)에 이슈로 남겨 주세요.
